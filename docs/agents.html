Agents and recipes

The SDK can run as a CLI, a Python API, a stdio MCP server, and an ARWS-compatible manifest source. Use ODPR recipes when the workflow itself needs a repeatable contract.

MCP server

Use MCP after the CLI works locally. The agent host launches open-data-products serve and calls SDK tools over stdio, so the host environment must have the same package installed and the same file permissions as your terminal workflow.

MCPstdio server
open-data-products serve
open-data-products manifest --json

Codex configuration

.codex/config.tomlportable command
[mcp_servers.open_data_products]
command = "open-data-products"
args = ["serve"]
enabled = true
startup_timeout_sec = 10
tool_timeout_sec = 60

Install the package in the same environment the agent host uses. The command is intentionally portable and assumes open-data-products --help works on PATH.

What the agent surface is for

Read and validate

Validation, explanation, reference discovery, summaries, and resource discovery.

Search and reason

Vocabulary search, graph traversal, graph summaries, graph analysis, and focus-node context.

Context bundles

OKF bundle validation and OKF concept listing without returning full Markdown bodies.

Product-contract context

Contract reference resolution, alignment checks, schema summaries, and product-level reports.

ODPR recipes

ODPR recipes are workflow contracts. They describe ordered SDK steps, providers, inputs, outputs, validation gates, context formats, write policy, review policy, and run manifests.

Use recipes when the same workflow must run repeatedly in a project, CI job, or agent-led process. The dry run shows resolved step parameters, planned writes, provider readiness, review requirements, and blocking reasons before any write-heavy or provider-backed execution.

Starter workflowdry-run first
open-data-products recipe list --json
open-data-products recipe init build-data-product-portfolio --parameterized --json
cd recipes/build-data-product-portfolio
open-data-products recipe explain recipe.yaml --json
open-data-products recipe plan --json
Configured projectreview before execute
open-data-products config recipes --copy-to recipes.config.yaml
open-data-products config recipes --config recipes.config.yaml --check --json
open-data-products recipe list --config recipes.config.yaml --json
open-data-products recipe validate recipes/ci-validate.yaml --json
open-data-products recipe run recipes/ci-validate.yaml \
  --config recipes.config.yaml \
  --dry-run \
  --json

Boundary: use CLI or Python for artifact-writing workflows. Use MCP when agents need safer discovery, validation, search, summary, and context operations.
